# 照片到播放的完整交互优化

用户已于本轮确认整体优化此前提出的流程。目标是降低首次播放和向已有相框追加照片的操作成本，消除来源连接强制新建相框、重复选片、草稿丢失和返回失效。

## 产品行为

- 首次使用选择来源后进入选片，明确确认展示后保存并播放。内部自动建立默认命名相框，名称后续可改，首次无需填写名称或进入播放设置。
- 来源管理连接、编辑、重新授权完成后返回来源列表并提供明确结果。来源权限和展示授权独立，连接来源不自动公开照片。
- 已有相框添加照片携带目标相框及完整编辑草稿，确认后合并到当前相框。新建相框只由明确新建入口或首次确认播放创建。
- 系统选择的具体文件保留本次范围，目录/相册进入该范围的选片。任何自动预选仅形成待确认草稿。
- 编辑切换来源、目录、AI或返回保留未提交状态，无法安全保留时先明确保存/放弃，不默默覆盖。取消不产生空相框或丢失原有内容。
- 保存有防重复提交、忙碌反馈和可重试错误，失败保留草稿。返回按实际导航容器退出，保存成功回到正确来源页面或播放。
- 检查空态、加载、错误、断网、授权取消/撤销、横竖屏/大字与中英文表达，修复本轮涉及流程内的确认问题。

## 实现约束

沿用 Swift/UIKit 与 Kotlin Views，iOS 15+、Android API 29+。中英文。沿用现有数据库、引用与按需缓存，不复制本机原图，不写回源端。17表不增加。禁止新增代码注释、SDK、生产签名动作或商店提交。历史用户数据及手动排除必须保留。16仅主Agent回填。

## 方案选择

采用按入口保留任务上下文的流程。保留相框作为持久播放配置，首次自动命名并在确认后创建。完全移除相框概念会破坏现有多套播放配置，所有入口继续强制进入新建页则无法解决本轮问题。

## 验证

覆盖首次确认播放、管理来源不建相框、已有相框追加、系统多文件范围、跨编辑草稿、取消返回、保存失败与重复点击。双端构建/静态分析/已有测试和有针对性的原生回归，实际模拟器关键路径验证。未运行的真机和外部服务路径明确记录。

## 导航依据

返回沿用户进入路径退出并保留页面状态，完成一次性首次流程后清除该流程的返回路径。采用既有原生容器实现。参考 [Android navigation principles](https://developer.android.com/guide/navigation/principles) 与 [Apple navigation and search](https://developer.apple.com/design/human-interface-guidelines/navigation-and-search)。
